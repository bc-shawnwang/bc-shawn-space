Order search · "On Backorder" filter returns zero past page 1

OrderElasticSearch::filterOrders pages correctly on page 1, then returns empty results for every page after that — even though the total count says there are more orders.

Introduced in PR #63438 — feat(orders): ORDERS-7031 add "On Backorder" filter to View Orders page
Discussion Slack thread · #C04D0Q2LC
Entry point Bigcommerce\Order\Infrastructure\Search\OrderElasticSearch::filterOrders()

Root cause

Pagination is applied twice: once when Elasticsearch fetches only the current page's order IDs, and again when DataModel_PagedCollection appends LIMIT/OFFSET to the SQL query that's already scoped to just those IDs. For page ≥ 2, the re-applied offset skips past every row in the already-page-sized result set → zero rows, regardless of how many backordered orders actually exist.

Fix direction

  • OrderSearch::search() shouldn't re-slice a result set that's already been paginated upstream by the ES call.
  • Mirror the existing $partialArrayCollection escape hatch in PagedCollection.php:92 (used for the array-collection branch) for the SelectQuery branch at PagedCollection.php:112-119, so a caller can say "this query is already scoped to one page — don't add LIMIT/OFFSET again."
  • The total count (getUnlimitedCounts()) is correct and independent of paging, so pagination links/totals render fine — only the row fetch for page ≥ 2 is broken.
