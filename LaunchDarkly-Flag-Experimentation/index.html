Two features, one hash function

A percentage rollout and an Experiment iteration aren't two settings on the same feature — they're two different parts of LaunchDarkly. A rollout is a targeting-rule option that ships with every flag. Experimentation is a separate product built on top of flags, with its own audience allocation and iteration lifecycle. Both walk the same weighted-variation hash underneath — what differs is where the seed comes from and when it's allowed to move.

1 ·Standard rollout vs. Experiment iteration

Short version: a rollout's hash prefix is fixed at flag creation and never regenerates. An experiment's hash prefix is tied to its current iteration — starting a new one can mint a fresh seed, which recomputes every context's bucket even though the ramp % threshold itself didn't move.

Use case examples
  • Canary launch — ship a new checkout flow to 1% of traffic, ramp to 100% over weeks if nothing breaks
  • Staged deprecation — move a legacy API off 5%, then 25%, then 100% of callers on a fixed schedule
  • Permanent cohort — give a fixed 10% of enterprise accounts early access to a feature indefinitely
  • Ops-style kill switch — gate a risky code path behind a slowly increasing percentage, no metrics attached
  • A/B test — compare two checkout button colors against a click-through-rate metric until significant
  • Funnel optimization — test signup step order and measure drop-off at each stage
  • User-day experiment — re-randomize daily on purpose to cancel out weekday/weekend behavior swings
  • Multi-armed bandit — shift traffic toward whichever variation is currently winning on a live metric

3 ·What this shows

  • Standard mode: drag the slider up, and "dropped" stays at zero no matter what. The prefix never moves, so raising the threshold can only extend the range a context already sits in — never evict it.
  • Experiment mode, checkbox off: click "Save & start new iteration" and watch the odometer flip. Even a straight increase, 6% → 30%, can drop contexts that were previously in — because the whole number line got re-drawn under them, not just the threshold.
  • Experiment mode, checkbox on: raise the ramp and the odometer holds — same seed, same behavior as standard mode. Now lower it and raise it again: the seed flips anyway, on schedule, exactly as documented.
  • Stop → start: mints a new seed unconditionally. It's the one action in this whole widget the checkbox can't touch.
