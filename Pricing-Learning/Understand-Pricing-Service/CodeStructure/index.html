6. The composition root

Boot.scala (546 lines) builds every client, repository, cache and service by hand, with no dependency injection framework, then registers the gRPC services. EventListenerBoot.scala (522 lines) does the same for the listener process. The order below is the order in the file.

LinesSectionWhat is built
84 - 125ExecutorsPricingAsyncThreadPool (a work-stealing pool, with gRPC context, MDC and tracing carried across threads), the actor system, Prometheus metrics, and the fixed database thread pool.
126 - 138RPC stubsAn RpcClientProvider per downstream service: Storefront Config, Inventory, Workload Manager, and later Catalog, Category, Channels, Currency, Customer Group Validation.
139 - 226Config, Redis, cachesServiceConfig, the persistence Redis connection (Kryo codec for the currency projection), and the Caffeine, Lettuce and two-level cache builders.
227 - 244DatabaseStoreDbConfig, the LaunchDarkly client, StoreDbPoolProvider and StoreDb, with a retry filter for deadlocks and unknown tables.
245 - 262Events and staff logsThe RabbitMQ publisher for price list events, and the notification services that write staff logs.
263 - 328TaxZone, rate and customer address repositories with their caches, the projection and determination services, and TaxImpl.
329 - 429Price listsStore config client and its caches, the price list, record, layer and assignment repositories and services, and PriceListsImpl.
430 - 466Clients and discountsCatalog, currency and cart catalog clients, the currency provider, the discount repositories and service, and DiscountsImpl.
467 - 528PricingPrice list assignment, price resolution, overview pricing, tax application, PricingService, CartPricingService, and the Impl classes.
529 - 534RegistrationSix register(...Grpc.bindService(impl, PricingAsyncThreadPool)) calls.

When you add a service, repository, cache or client, wire it here. If the event listener also needs it, wire it in EventListenerBoot too: the two files build their own copies. Both are excluded from code coverage in build.sbt.

  • Three test configs. Test is unit. FunTest (fun) is functional and talks to a real store database; set FUN_TESTS_STORE_ID. IntTest (it) is integration and uses a Flyway-managed schema. The price-lists directory is named Integration on disk while the build points at src/integration, which only resolves on a case-insensitive file system.
  • Run everything: ./script/test runs testAll, which runs each module's unit, integration and functional tests in order. test inside sbt means testQuick in sbt 2, so testAll uses testFull.
  • CI (.circleci/config.yml, job test-and-validate): scalafmtCheckAll, then cleanFull compile coverage testAll coverageAggregate, with a MySQL executor. Test results are relabelled by module. The PHP acceptance and API tests run in separate jobs.
  • Format: sbt scalafmtAll, config in .scalafmt.conf.
  • Test file counts (Scala): common 9, price-lists 33 + 4 integration + 3 functional, tax 44, pricing-impl 41 + 4 functional, root 5.

9. Where new code goes

You want toPut it in
Add or change an RPC methodThe proto is in services-scala, so update that dependency first. Then the matching *Impl: keep it thin, add a converter, a validator if needed, and a service method.
Add business logicA service class in the module that owns the data. Keep decisions in pure functions, as PriceAdjusters does, and put I/O at the edges.
Read or write the databaseA trait in repository and a StoreDb* class in repository/db. For heavy writes, consider WorkLoadManagerGatedRepository, which two price-lists repositories use.
Call another serviceA client class around its stub, and a stub provider in Boot.
Cache somethingAdd a named entry in application.conf, get it from a cache builder in Boot, and wrap the repository or client. Use the two-level builder for store config style data.
React to an eventA handler class, a Consumer(queue) in EventListenerBoot, and the services it needs wired there too.
Gate a change with a flagA LaunchDarkly flag read through ldClient. Price list flags go in PriceListFeatureFlagList.
Share code between modulescommon, but only if every module needs it. A module can depend on a module below it, never above.

10. Observations

ObservationDetail
Wiring is written twice.Boot and EventListenerBoot each build their own StoreDb, caches and services. A change to how a shared service is built has to be made in both.
One name for two things.In Boot, currencyProjectionService is a ProjectingCurrencyProvider (the reader). The class named CurrencyProjectionService, in the event package, is the updater used by the listener.
Large files.StoreDbPriceRecordRepository is 1,277 lines and PriceListsImpl is 558. Boot and EventListenerBoot are over 500 each.
Impl classes call each other.TaxApplicationService takes taxImpl, the gRPC binding itself, instead of a service. So the tax module's public surface is its Impl.
Not read.The bodies of most services and repositories outside the paths on this page, the Terraform, docs/ and the PHP tests.
